# Fire

*[English](README.md)*
*[변경 이력](CHANGELOG.md)* · *[릴리즈 방법](docs/RELEASING.md)*

macOS 메뉴바 아이콘을 **메인 메뉴바**와 **Fire Bar** 두 구역으로 정리하는 초경량
메뉴바 앱입니다.

아이콘이 많아 메뉴바가 넘칠 때, 자주 쓰지 않는 것들을 접어 두었다가 필요하실 때만
꺼내 쓰실 수 있습니다. 앱은 1.3MB, 상주 메모리는 74MB입니다.
Dock 아이콘 없이 메뉴바에만 있습니다.

## 다운로드

**[Fire 0.1.1 내려받기 (dmg)](https://github.com/kimhung910924/fire-menubar/releases/latest)**

- macOS 14 Sonoma 이상이 필요합니다
- Apple 공증을 마쳤습니다. 경고 없이 바로 열립니다
- dmg를 열고 Fire를 `응용 프로그램`으로 끌어다 놓으시면 됩니다

처음 실행하시면 **손쉬운 사용**과 **화면 기록** 권한을 요청합니다. 메뉴바 아이콘을 옮기고
모양을 읽는 데 씁니다. 화면 내용은 저장하거나 전송하지 않습니다.

## 최초 설정

1. 앱을 실행하시면 설정창이 뜹니다.
2. **손쉬운 사용** 권한을 켜 주세요. → 시스템 설정 › 개인정보 보호 및 보안 › 손쉬운 사용
3. **화면 기록** 권한을 켜 주세요. → 시스템 설정 › 개인정보 보호 및 보안 › 화면 기록
4. 권한을 켜신 뒤 Fire를 다시 실행해 주세요.
5. 설정창에서 숨기고 싶은 아이콘을 `Fire Bar에 표시` 구역으로 끌어다 놓으시면 됩니다.
   구분자 위치는 Fire가 알아서 맞춥니다.
6. 주황색으로 표시된 아이콘이 있으면, 메뉴바에서 `⌘` 키를 누른 채 **그 아이콘 자체를**
   옮겨 순서를 맞춰 주세요. 이유는 아래 "OS 제약"에 적어 두었습니다.

## OS 제약 — 꼭 읽어 주세요

기획안 24절 "Private API 가능성"에 해당하는 부분입니다. 구현하면서 macOS 26에서 직접
측정해 확인한 내용입니다.

### 1. 다른 앱의 status item을 직접 숨기거나 재배치할 수 없습니다

공개 API에는 그런 수단이 없습니다. Ice와 Bartender를 포함해 모든 메뉴바 정리 앱이 쓰는
유일한 방법은 **자기 소유의 status item(구분자) 폭을 화면 너비만큼 늘려서 그 왼쪽 항목을
화면 밖으로 밀어내는 것**입니다. Fire도 같은 방식을 씁니다
([ControlItemCoordinator.swift](Sources/Fire/StatusItem/ControlItemCoordinator.swift)).

그래서 **숨김은 메뉴바에서 연속된 구간에만 걸 수 있습니다.** 구분자 왼쪽이 통째로
숨겨지기 때문입니다.

### 구분자는 Fire가 스스로 옮깁니다

macOS는 status item의 위치를 **그 앱 자신의** 사용자 기본값에 저장합니다.

```
키:  NSStatusItem Preferred Position <autosaveName>
값:  메뉴바가 있는 화면의 오른쪽 끝에서 그 항목까지의 거리(pt)
```

남의 항목은 그 앱의 기본값이라 손댈 수 없지만, **Fire 자신의 구분자는 옮길 수 있습니다.**
그래서 구분자를 손으로 끄실 필요가 없습니다. 분류를 바꾸시면 Fire가 경계를 다시 계산해
맞춥니다.

값과 실제 배치의 관계는 측정으로 확정했습니다. 구분자는 `(화면 오른쪽 − 값)` 좌표를
**품고 있는 항목의 바로 왼쪽**에 끼어듭니다.

```
값 458 → 3390-458 = 2932  (Owly와 pizzaClip의 경계) → Owly 왼쪽에 삽입  (Owly 안 숨겨짐)
값 445 → 3390-445 = 2945  (pizzaClip 안쪽)          → pizzaClip 왼쪽에 삽입 (Owly 숨겨짐)
값 420 → 3390-420 = 2970  (TextInput 안쪽)          → pizzaClip까지 숨겨짐
```

그래서 항목의 **경계**가 아니라 남길 첫 항목의 **한가운데**를 노려야 합니다. 경계를 노리면
어느 쪽에 붙을지 갈려서 한 칸씩 어긋납니다.

주의할 점이 하나 더 있습니다. status item을 제거하면 macOS가 저장된 위치 값을 **지웁니다.**
그래서 `제거 → 값 기록 → 재생성` 순서를 지켜야 합니다. 반대로 하면 기록한 값이 사라집니다.

### 그래도 남는 한계가 있습니다

분류가 메뉴바의 연속 구간과 다르면 어긋납니다. 아이콘의 물리적 순서는 Fire가 바꿀 수
없기 때문입니다.

- FIRE_BAR로 지정했는데 경계 오른쪽이라 숨겨지지 않는 항목
- MAIN으로 지정했는데 경계 왼쪽이라 함께 숨겨지는 항목

둘 다 설정 화면에 주황색으로 표시합니다. 해결하시려면 메뉴바에서 `⌘`+드래그로
**아이콘 자체의 순서**를 바꿔 주셔야 합니다.

### 설정 화면은 실제 메뉴바 순서로 보여 드립니다

저장된 `order`는 드래그로 정하신 희망 순서일 뿐입니다. 실제로 무엇이 숨겨지는지는 물리적
위치가 결정하므로, 희망 순서를 보여 드리면 눈앞의 메뉴바와 어긋나 보여 혼란만 드립니다.
그래서 목록은 항상 측정한 물리적 순서로 정렬합니다.

메커니즘 자체는 측정으로 검증했습니다.

```bash
./.build/app/Fire.app/Contents/MacOS/Fire --verify-hide
# 또는: open -n .build/app/Fire.app --args --verify-hide
```

```
구분자 확장 전 : 18개
구분자 확장 후 : 16개
숨겨진 항목    : 2개
복원 후        : 18개 (정상 복원)
```

새 status item은 항상 메뉴바의 가장 왼쪽에 생기므로, 갓 설치하신 직후에는 구분자 왼쪽에
아무것도 없습니다. 구분자를 오른쪽으로 옮기셔야 숨길 대상이 생깁니다.

### 2. status item의 소유 PID를 믿을 수 없습니다

macOS 26에서는 모든 status item 윈도우의 `kCGWindowOwnerPID`가 **제어 센터**를 가리킵니다.
실제 소유 앱은 다음 순서로 알아냅니다
([MenuBarScanner.swift](Sources/Fire/MenuBar/MenuBarScanner.swift)).

1. 접근성 `AXExtrasMenuBar` 열거 — 가장 정확하지만 손쉬운 사용 권한이 필요합니다
2. `kCGWindowName`에 들어 있는 번들 식별자 — 권한 없이도 읽히지만 항목에 따라 `Item-0`만
   오는 경우가 있습니다
3. 메뉴바 오른쪽 기준 상대 순서 — 마지막 수단입니다 (기획안 14절)

주의할 점 세 가지를 측정으로 확인했습니다.

- **`kCGWindowName`의 번들 식별자가 이웃 항목의 것일 때가 있습니다.** 그래서 접근성이 소유
  앱을 알려준 항목에서는 창 이름을 소유자 판단에 쓰지 않고, `WiFi`·`Battery`·`Clock`처럼
  한 앱의 여러 항목을 구분하는 용도로만 씁니다.
- **접근성 호출은 기본 타임아웃이 6초라, 앱 전체를 순회하면 20초 넘게 멈춥니다.**
  `AXUIElementSetMessagingTimeout`으로 0.25초로 끊어 2초 안에 끝나게 했습니다.
- 접근성 제목(`배터리 62%`, `Itsycal, 8월 1일`)은 계속 바뀌므로 표시용으로만 쓰고
  식별자에는 넣지 않습니다.

### 식별자는 권한 상태와 무관해야 합니다

번들 식별자는 접근성 권한이 있어야만 알 수 있습니다. 그래서 번들 식별자를 우선하면,
권한을 껐다 켜실 때마다 같은 항목의 식별자가 바뀌어 저장된 배치가 통째로 사라집니다.

그래서 순서를 뒤집었습니다. **항목 고유 이름(`WiFi`, `Battery`, `Clock`)을 번들 식별자보다
먼저** 봅니다. 고유 이름은 권한 없이도 읽히므로 어느 쪽이든 같은 식별자가 나옵니다.
측정으로 확인했습니다.

```bash
# 권한 있음(번들 실행)과 권한 없음(셸 직접 실행)의 결과가 같아야 합니다
open -n .build/app/Fire.app --args --dump && cat ~/Library/Application\ Support/Fire/dump.txt
./.build/app/Fire.app/Contents/MacOS/Fire --dump
```

### 캡처한 아이콘은 그대로 쓸 수 없습니다

- 메뉴바 글리프는 배경에 따라 흰색으로 캡처됩니다. 밝은 설정 창에 얹으면 보이지 않습니다.
  단색으로 판별되면 알파만 남겨 `labelColor`로 다시 칠합니다
  ([MenuBarIconRenderer.swift](Sources/Fire/MenuBar/MenuBarIconRenderer.swift)).
- 서드파티 앱 상당수는 캡처하면 **투명한 이미지만** 나옵니다. 그리기가 제어 센터 쪽에서
  일어나기 때문으로 보입니다. 이 경우 소유 앱의 아이콘으로 대체합니다.

### 3. 디스플레이마다 메뉴바 윈도우가 따로 생깁니다

같은 항목이 디스플레이 수만큼 중복되고, 보조 디스플레이용 사본은 이름에 `Clone`이 붙습니다.
스캐너는 화면 소속으로 행을 나누고, 사본과 화면 밖 윈도우를 걸러낸 뒤, 항목이 가장 많은
행을 기준으로 삼습니다.

## 구조

```
Sources/Fire/
├── App/              진입점, 조립, 진단 모드
├── StatusItem/       Fire 아이콘 + 구분자 (숨김 메커니즘)
├── MenuBar/          탐색 · 식별 · 구역 적용 · 클릭 프록시
├── FireBar/          패널 · 아이콘 뷰 · 위치 계산
├── Events/           빈 영역 판정 · 전역 클릭 · 단축키 · 시스템 이벤트
├── Stability/        재구성 코디네이터 · Watchdog
├── Settings/         설정창 · 저장소
├── Updates/          Sparkle 자동 업데이트
├── Permissions/      손쉬운 사용 · 화면 기록
└── LoginItem/        SMAppService
```

데이터는 `~/Library/Application Support/Fire/`에 저장합니다.
PID, 윈도우 번호, 디스플레이 번호, 화면 좌표, 캡처 이미지는 저장하지 않습니다
(기획안 22절).

## 권한이 붙지 않을 때

시스템 설정 목록에는 Fire가 켜져 있는데 앱은 권한이 없다고 한다면, **서명이 바뀐
것입니다.** TCC는 권한을 코드 서명 신원에 묶습니다. ad-hoc 서명(`-`)은 신원이 없어
바이너리 해시로 기억하므로, 리빌드할 때마다 승인이 무효가 됩니다.

`build.sh`는 `Apple Development` 인증서를 자동으로 찾아 씁니다. 인증서가 있으면 팀
식별자로 신원이 고정되어 리빌드해도 승인이 유지됩니다. 다른 인증서를 쓰시려면 이렇게
하시면 됩니다.

```bash
FIRE_SIGN_IDENTITY="Developer ID Application: ..." ./build.sh release
```

ad-hoc으로 빌드된 적이 있다면, 시스템 설정에서 기존 Fire 항목을 **삭제하신 뒤 다시
추가**해 주셔야 합니다.

## 아직 검증되지 않은 것

권한을 켠 실제 환경에서 확인해야 하는 항목입니다. 기획안 25절 Phase 0에 해당합니다.

- [x] 접근성 경로로 소유 앱 식별 — 16개 항목 전부 정확히 식별 (`--dump`)
- [x] 구분자 확장으로 실제 숨김과 원상 복원 (`--verify-hide`)
- [x] Fire Bar 아이콘 클릭이 원본 앱 메뉴를 여는지 — 메뉴가 화면 안에 열리는 것까지
      확인했습니다. 다만 메뉴가 유지되는지는 HiddenNotch 1.2 이후 재확인이 필요합니다
- [ ] 왼쪽·오른쪽 빈 영역 클릭이 Apple 메뉴와 앱 메뉴를 방해하지 않는지
- [ ] 노치 주변 좌표 처리
- [ ] 외부 모니터 20회 연결·해제 후 자동 복구
- [ ] 잠자기 10회 복귀 후 자동 복구
- [ ] 클램셸 모드 진입·해제

## 이름

기획안 3절에 적힌 대로, Ice 기반의 같은 이름 공개 프로젝트가 있어서 외부 배포 전에
이름을 다시 검토합니다.
